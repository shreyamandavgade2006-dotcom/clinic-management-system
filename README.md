# Smart Student Management System (SSMS)

A complete **MERN** (MongoDB · Express · React · Node) student management platform for **Teachers** and **Students**, with an **AI question & assessment generator**, attendance analytics with **75% defaulter flagging**, **WhatsApp guardian alerts**, marks/results, assignments, exams, notifications and role-based dashboards.

> The repository root holds this MERN application. The original PHP clinic project is preserved untouched in [`clinic-management/`](./clinic-management) for reference.

## Feature overview

**Student**
- Secure login, profile, guardian & academic details, password change
- Attendance view with subject-wise %, monthly trend and a "below 75%" warning state
- Marks, grades, results, performance trend, strong/weak subject analysis and CGPA
- Assignments: list, detail, submit work (text + link), see grades & feedback
- Exam schedule and day-wise timetable with syllabus + instructions
- AI quizzes: attempt with a live timer and question palette, auto-submit, instant score, grade, answer review and topic-wise breakdown
- Announcements and a notification centre (assignments, exams, results, attendance alerts)
- Dashboard with attendance, performance, pending work and recent activity

**Teacher**
- Dashboard: class summaries, attendance %, defaulters, toppers, pending grading, recent AI quizzes and WhatsApp log
- Student management: profiles, academic details, search, class & attendance filters, add/edit, bulk import, CSV export, delete
- Student detail: attendance trend, subject-wise performance, marks sheet, submissions, quiz attempts, guardian alert action
- Subjects & syllabus: create subjects, map units + topics (these drive the AI generator), per-subject analytics
- Attendance: fast marking UI (present/absent/late/excused, all-present shortcut), class board, today's summary and the **below-75% defaulter list**
- Marks: bulk marks entry per subject/exam with live grade preview + class analytics (subject averages, grade distribution, ranking, toppers, needs attention)
- Assignments: create, publish/draft, track submissions, grade with feedback, remind pending students over WhatsApp
- Exams: schedule/edit exams, syllabus & instructions, notify the class, day-wise timetable, reminders
- AI quizzes: manage everything generated by the AI engine with live attempt analytics and manual review of long answers
- AI Question & Assessment Generator: subject → unit → topic → difficulty → question type → count → marks, preview, edit, save as quiz/assignment
- Analytics: class comparison, attendance board, grade distribution, subject averages, complete ranking, leaderboard
- Announcements & notifications: publish notices (categories, priority, pinning, scheduling) and push in-app notifications
- WhatsApp alerts: provider status, defaulter list, dry-run preview, one-click send, per-student alerts and a full delivery log
- Faculty profile: designation, department, qualification, cabin, subjects taught, security settings

## Quick start

```bash
# 1. install dependencies for root, server and client (one command)
npm run install:all

# 2. (optional) configure env — everything has a working default
cp server/.env.example server/.env

# 3. run the API and the web app together
npm run dev
#    API     → http://localhost:5000
#    Web app → http://localhost:5173
```

Prefer separate terminals?

```bash
npm run dev:server   # express API with --watch
npm run dev:client   # vite dev server (proxies /api → localhost:5000)
```

Production build:

```bash
npm run build        # builds client/dist
npm start            # serves the API (serve client/dist with any static host)
```

Requirements: **Node 18+** and npm (`node -v` to check; get it from [nodejs.org](https://nodejs.org) → LTS). MongoDB is optional — see [storage modes](#storage-modes).

> **Windows tip:** open the project folder in File Explorer, click the address bar, type `cmd` and press Enter — that opens a terminal already inside the project. Use Command Prompt if PowerShell blocks `npm` with a script-execution policy error.

## Storage modes

`server/src/config/db.js` connects to MongoDB when it is reachable and otherwise boots a **drop-in in-memory store** with the same Mongoose-style API (queries, `populate`, updates, aggregation helpers) that is seeded with the demo dataset. This means the whole product can be reviewed with zero infrastructure. The active mode is reported by `GET /api/health`:

```json
{ "database": { "mode": "memory", "host": "in-memory demo store" } }
```

Set `ALLOW_IN_MEMORY_FALLBACK=false` to make a missing MongoDB a hard error, and run `npm run seed` to populate a real database.

## How the AI generator works

1. Teacher picks a **subject → unit → topic**, difficulty, question type, question count and total marks in `/teacher/ai-generator`.
2. `POST /api/quizzes/generate/preview` asks the AI service for a paper. The service builds a strict prompt from the syllabus topics and expects JSON; the request is submitted to:
   - **Gemini** (`GEMINI_API_KEY`) or **OpenAI** (`OPENAI_API_KEY`) when configured, otherwise
   - the **built-in offline generator**, which composes questions from the subject's unit/topic data (MCQ, true-false, numerical, short/fill-blank and long answer templates with a balanced difficulty mix).
   Remote failures automatically fall back and are reported in the response as `fallback: { from, reason }`.
3. The teacher previews the paper, can edit marks/questions, then saves it as a **quiz** (attemptable online) or an **assignment** (question paper with written submission). Generated papers can be copied, downloaded or printed.
4. Students attempt the quiz in a timed runner; `POST /api/quizzes/:id/submit` evaluates automatically — MCQ/true-false exactly, numerical within ±0.01, short answers by keyword overlap (full ≥ 60%, half ≥ 30%), long answers flagged `needsManualReview` for teacher review — then writes an internal `Mark`, raises notifications and returns score, percentage, grade and topic-wise breakdown.

AI is used **only** for quiz/assignment/question-paper generation, as required.

## How WhatsApp attendance alerts work

1. Attendance saved with a status of `absent` lowers the student's running percentage.
2. `attendanceAlertService` scans students whose attendance is below `ATTENDANCE_THRESHOLD` (default **75%**), computes the shortfall, the sessions still needed and the weakest subject.
3. Each guardian is messaged through the configured provider — Twilio, Meta Cloud API, or the console/simulation provider used when no credentials exist (messages are still stored in the alert history with status `simulated`, so the flow is fully demonstrable).
4. Duplicate alerts are suppressed by a cooldown, students without a guardian number or with `whatsappOptIn: false` are skipped, and every attempt lands in `WhatsAppLog`.
5. Triggers: automatically after an attendance session where students are absent, per-student "Notify guardian" buttons, the teacher's **WhatsApp Alerts** page (dry-run preview → send), or the scheduled job:

```bash
npm run attendance:alerts                          # scans every class
npm run attendance:alerts -- --class=TE-A          # limit to one class
npm run attendance:alerts -- --dry                 # preview only, no messages
npm run attendance:alerts -- --threshold=80        # override the threshold
```

Set `WHATSAPP_ALERT_CRON=true` (with `WHATSAPP_ALERT_INTERVAL_HOURS`, default 6) to let the API run the scan automatically in the background.

## Attendance & grading rules

- **Attended** statuses: `present`, `late`. **Absent**: `absent`. **`excused`** (approved leave) is excluded from the denominator.
- A student is a **defaulter** below **75%** of countable sessions; the API returns the shortfall, the number of consecutive sessions needed to recover and a risk level (`critical`/`high`/`moderate`).
- Grades: `O` ≥ 90, `A+` ≥ 80, `A` ≥ 70, `B+` ≥ 60, `B` ≥ 50, `C` ≥ 45, `P` ≥ 40, else `F`; grade points feed CGPA.
- Any record can be updated through `PUT /api/attendance/:id` — dashboards, analytics and defaulter lists recalculate immediately.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `GET /api/health` shows `"mode": "memory"` | MongoDB is not running — start `mongod`/Atlas and set `MONGO_URI`, or keep exploring on the demo store. |
| AI papers look templated | No AI key configured — set `GEMINI_API_KEY` or `OPENAI_API_KEY` (the response also carries a `fallback` note explaining it). |
| WhatsApp messages show as `simulated` | Expected with `WHATSAPP_PROVIDER=console`; add Twilio/Meta credentials to send for real. |
| Login returns 401 | Wrong credentials, or the seeded demo store was reset — restart the API to reseed. |
| Client cannot reach the API | The Vite dev server proxies `/api`; make sure the API runs on port 5000 (or update `vite.config.js`). |
| Port already in use | Change `PORT` (server) or run `npm run dev:client -- --port 5174`. |
| `sh: concurrently: not found` when running `npm run dev` | Root tools were not installed — run `npm install` in the project root once, then `npm run dev` again (fixed in current versions of `install:all`). |
